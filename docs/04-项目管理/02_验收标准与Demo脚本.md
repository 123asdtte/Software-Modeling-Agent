# 验收标准与 Demo 脚本（v13）

> 给"陈老师 / 任总 / 董事长"展示的验收口径。Demo 前逐项核对本清单。

---

## 1. 功能验收标准

| 模块 | 验收项 | 标准 |
|---|---|---|
| 智能问答 | 教材知识库问答 | 回答有教材依据 + 来源标注 |
| 智能问答 | 无命中兜底 | 不编造，明确提示 |
| PPT 生成 | 大纲完整 | 含首页/目标/讲解/案例/互动/练习/总结 |
| PPT 生成 | 文件输出 | .pptx 可打开编辑、中文无乱码 |
| 教案生成 | 字段完整 | 9 个必填字段齐全 |
| UML 建模 | 需求→图 | 自然语言输入 ≤30s 出图，**六图型全覆盖**：用例图 / 活动图 / 状态机图 / 类图 / 时序图 / 部署图（PNG + draw.io 可编辑 XML） |
| UML 质检 | 分图校验拦截 | 六套规则组（UC/AC/SM/CL/SQ/DEP）评测集通过率 ≥ 90%；典型错误用例 100% 拦截 |
| UML 质检 | 双重验证 | 规则 + LLM 复核两层，可演示 |
| 正向工程 | 类图→代码 | 类图一键生成 **Java 骨架代码**（包名/可见性/extends/implements/抽象方法），可单文件下载 |
| 辅助实践 | 互动点体系 | 43 个互动点已登记全景表；首期 3 类图（用例图/活动图/状态机图）互动点有落地形态（启发/审查/辨析/综合验证） |

## 2. 质量验收标准

- 全项目测试通过（pytest）、覆盖率达标（核心 ≥ 80%）；
- ruff / mypy 无错误；
- 安全：无明文密钥、鉴权限流生效、上传校验生效；
- 性能：问答首响 ≤5s、PPT/教案 ≤60s、UML ≤30s；
- 文档：PRD/技术方案/规范与代码同步。

## 3. Demo 演示脚本（领导展示版）

**主题：《AI 辅助软件建模教学》**

### 环节 1：智能问答（辅助教学）
- 输入：`解释什么是用例图`
- 展示：概念解释 → 通俗案例（电影剧本类比）→ 教材来源标注
- 讲解词："AI 不是搜索引擎，回答基于我们教材知识库，带来源。"

### 环节 2：自动生成教学资源（辅助教学）
- 输入：`生成 90 分钟用例图教学 PPT`
- 展示：PPT 目录（课程目标/知识讲解/案例分析/课堂互动/练习/总结）→ 下载 PPT
- 可补：`生成《用例图》教学设计` → 教案结构
- 讲解词："老师备课从几小时缩短到几分钟，AI 出初稿，老师做审核。"

### 环节 3：UML 生成 · 静态结构（辅助设计）
- 输入：`设计校园报修系统。学生提交报修，管理员审核，维修人员处理。`
- 展示：
  - 分析结果：参与者（学生/管理员/维修人员）、用例（提交报修/审核报修/维修处理）
  - 点击"生成 UML 图" → 自动出**用例图** PNG
  - 下拉切到**类图**，输入：`校园选课系统：学生与课程多对多，学生继承用户基类，实现选课接口 Enrollable，教师发布课程`
  - 展示类框（属性/方法/可见性/抽象接口）、六种关系箭头（泛化/实现/聚合/组合/关联/依赖）、质检报告
- 讲解词："从需求到用例图/类图，AI 自动完成。图上每个元素都能被规范校验，不是画着好看。"

### 环节 4：动态建模（辅助设计 · 教材任务六/七）
- 下拉切到**时序图**：`学生向选课服务提交请求，服务查余量，有余量则写库返回成功，否则返回名额已满`
  - 展示生命线、同步/异步消息、`alt` 分支片段
- 下拉切到**部署图**：`Nginx 网关 + 前端 Web 服务器 + K8s 集群（图书/借阅服务各 2 副本）+ MySQL 主从独立服务器`
  - 展示节点/构件、通信与依赖连线、K8s 语义质检（Service 无工作负载会告警）
- 每张图都点"下载 .xml"，用 draw.io 打开，证明**学生可以继续手工编辑**，不是死图
- 讲解词："时序图和部署图是教材后段的重头戏，平台不只出图，还给可编辑文件，学生能接着改。"

### 环节 5：正向工程（类图 → Java 代码）
- 停留在类图结果，点"生成 Java 骨架代码"，包名填 `com.campus.enroll`
- 展示：
  - 按类拆分的多个 `.java` 文件（`User` / `Student` / `Course` / `Enrollable` …）
  - `Student extends User implements Enrollable` 的声明推导
  - 抽象方法斜体对应到 `abstract`，具体方法带 `// TODO` + `UnsupportedOperationException`
- 讲解词："模型不是终点——类图能直接落成代码骨架。这就是教材里'正向工程'那一节，学生在平台上能亲手走一遍。"

### 环节 6：AI 质检（体现 AI 是教学专家）
- 故意输入：`设计订单系统，数据库作为参与者，学生点击提交按钮。`
- 展示 AI 拦截：
  - 边界：**数据库属于系统内部组件，不能作为参与者**；
  - 粒度：**"点击提交按钮"是操作步骤，不是业务目标，建议改为"提交订单"**。
- 同类演示（可任选其一）：
  - 类图输入循环继承 → `CL-CYC` 报错
  - 时序图输入引用不存在生命线的消息 → `SQ-REF` 报错
  - 部署图写 Service 但无工作负载 → `DEP-K8S` 告警
- 讲解词："AI 不只是画图工具，而是教学辅助专家——能像老师一样指出建模错误、讲清为什么错、给出修改建议。这就是教材里的边界粒度校验与双重验证。"

### 环节 5：收尾（可选）
- 展示项目目录与文档体系（本文件夹）：规范齐全、PRD 完整、可排期开发；
- 一句话总结："v13 不是简单接入大模型，而是基于 LangChain 构建面向教育场景的多智能体系统，让 AI 从'回答问题'升级为'辅助教学/辅助设计/辅助实践'的智能教学助手。"

## 4. 演示环境检查清单

**启动方式**：双击项目根目录 `启动服务.bat`。脚本会自动避开被占用的端口
（本机 8000 常被 Docker 容器占用），按 8000 → 8100 → 8101 顺序回退，
并在窗口里打印**本次实际使用的地址**。演示前记下这个地址。

- [ ] 服务已启动，窗口显示的实际端口 = 演示时访问的端口（不要凭记忆写 8000）；
- [ ] `http://127.0.0.1:<实际端口>/health` 返回 `status: ok` 且 `api_key_configured: true`；
- [ ] 模型可用（讯飞 Spark-X2.6）、额度充足；
- [ ] 知识库索引已构建（`app/knowledge_base/lightrag_index/` 存在，9.9MB）；
- [ ] PlantUML 本地渲染可用（`tools/plantuml.jar` 存在，PNG 能出）；
- [ ] draw.io 画布可渲染（`static/js/viewer.min.js` 已随仓库提供，2.8MB，**断网也能用**）；
- [ ] 演示数据固定（使用本脚本的固定输入，不现场自由发挥）；
- [ ] 六图型各跑一遍，记录每张图耗时（用 `demo_regression.py` 预演输出）；
- [ ] 降级预案：PlantUML 不可用 → 页面自动显示源码，仍可讲解；
- [ ] 提前完整跑通脚本 ≥ 2 次；
- [ ] 备好截图/录屏（防现场意外）。
