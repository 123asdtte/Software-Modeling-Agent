# 验收标准与 Demo 脚本（v13）

> 给"陈老师 / 任总 / 董事长"展示的验收口径。Demo 前逐项核对本清单。

---

## 1. 功能验收标准

| 模块 | 验收项 | 标准 |
|---|---|---|
| 智能问答 | 教材知识库问答 | 回答有教材依据 + 来源标注 |
| 智能问答 | 无命中兜底 | 不编造，明确提示 |
| PPT 生成 | 大纲完整 | 含首页/目标/讲解/案例/互动/练习/总结 |
| PPT 生成 | 文件输出 | .pptx 可打开编辑、中文无乱码 |
| 教案生成 | 字段完整 | 9 个必填字段齐全 |
| UML 建模 | 需求→图 | 自然语言输入 ≤30s 出图（用例图/活动图/状态机图 PNG） |
| UML 质检 | 分图校验拦截 | 三类图评测集通过率 ≥ 90%；典型错误用例 100% 拦截 |
| UML 质检 | 双重验证 | 规则 + LLM 复核两层，可演示 |
| 辅助实践 | 互动点体系 | 43 个互动点已登记全景表；首期 3 类图（用例图/活动图/状态机图）互动点有落地形态（启发/审查/辨析/综合验证） |

## 2. 质量验收标准

- 全项目测试通过（pytest）、覆盖率达标（核心 ≥ 80%）；
- ruff / mypy 无错误；
- 安全：无明文密钥、鉴权限流生效、上传校验生效；
- 性能：问答首响 ≤5s、PPT/教案 ≤60s、UML ≤30s；
- 文档：PRD/技术方案/规范与代码同步。

## 3. Demo 演示脚本（领导展示版）

**主题：《AI 辅助软件建模教学》**

### 环节 1：智能问答（辅助教学）
- 输入：`解释什么是用例图`
- 展示：概念解释 → 通俗案例（电影剧本类比）→ 教材来源标注
- 讲解词："AI 不是搜索引擎，回答基于我们教材知识库，带来源。"

### 环节 2：自动生成教学资源（辅助教学）
- 输入：`生成 90 分钟用例图教学 PPT`
- 展示：PPT 目录（课程目标/知识讲解/案例分析/课堂互动/练习/总结）→ 下载 PPT
- 可补：`生成《用例图》教学设计` → 教案结构
- 讲解词："老师备课从几小时缩短到几分钟，AI 出初稿，老师做审核。"

### 环节 3：UML 生成（辅助设计 · 重点）
- 输入：`设计校园报修系统。学生提交报修，管理员审核，维修人员处理。`
- 展示：
  - 分析结果：参与者（学生/管理员/维修人员）、用例（提交报修/审核报修/维修处理）
  - 点击"生成 UML 图" → 自动出用例图 PNG
- 可补：输入活动图/状态机图需求 → 演示多图类型支持（对齐教材任务六/七）
- 讲解词："从需求到用例图，AI 自动完成，用于课堂演示和作业辅助。首期支持用例图、活动图、状态机图三类。"

### 环节 4：AI 质检（体现 AI 是教学专家）
- 故意输入：`设计订单系统，数据库作为参与者，学生点击提交按钮。`
- 展示 AI 拦截：
  - 边界：**数据库属于系统内部组件，不能作为参与者**；
  - 粒度：**"点击提交按钮"是操作步骤，不是业务目标，建议改为"提交订单"**。
- 讲解词："AI 不只是画图工具，而是教学辅助专家——能像老师一样指出建模错误、讲清为什么错、给出修改建议。这就是教材里的边界粒度校验与双重验证。"

### 环节 5：收尾（可选）
- 展示项目目录与文档体系（本文件夹）：规范齐全、PRD 完整、可排期开发；
- 一句话总结："v13 不是简单接入大模型，而是基于 LangChain 构建面向教育场景的多智能体系统，让 AI 从'回答问题'升级为'辅助教学/辅助设计/辅助实践'的智能教学助手。"

## 4. 演示环境检查清单

- [ ] 演示数据固定（使用本脚本的固定输入，不现场自由发挥）；
