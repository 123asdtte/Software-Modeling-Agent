## 3. 依赖与并行

- W1 骨架完成后，QA（W2）与 PPT/教案（W3）可并行；
- UML 质检规则（纯代码）可与 W2 并行开发（不依赖模型）；
- 前端展示页可尽早搭壳（Mock 接口）。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 教材版权/授权问题 | 知识库入库受阻 | 先按公开课件/自编讲义演示，教材授权后补 |
| 大模型额度/费用 | 演示中断 | 设置上限、限流、本地缓存常用结果 |
| 模型生成不稳定（质检误报） | 演示翻车 | 规则引擎确定性为主，LLM 复核为辅；演示用例固定 |
| PlantUML 环境问题 | 出图失败 | Docker 内置；降级返回源码 |
| 2–4 周工期紧张 | 交付延期 | 按 P0 优先级：先问答+UML，PPT/教案可后置 |

## 5. 周会与汇报节奏

- 每周五：向陈老师汇报当周 Demo + 下周计划；
- 每阶段结束：提交阶段交付清单（代码 + 文档 + 测试报告）；
- 与任总同步：UML 效果对齐扣子版验收点（生成/质检/出图）。

## 6. 完成定义（DoD）

一个模块只有满足以下条件才算完成：
- 代码合入 develop（评审通过）；
- 单元/评测测试全绿；
- PRD 与代码一致（文档已更新）；
- 可在演示环境复现。
