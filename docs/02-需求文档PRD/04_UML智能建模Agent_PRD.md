# UML 智能建模 Agent · PRD（辅助设计 · 核心）

> 版本：v0.2 ｜ 方向：辅助设计 ｜ 优先级：P0（核心）｜ 状态：待开发
> 更新：2026-09-21，依据教材源稿扩展为多图类型
> 教材侧重点：AI 辅助软件建模教学——**用例图 / 活动图 / 状态机图三类图的生成、审查、优化**（首期），方法论为四步迭代法。

---

## 1. 功能概述

用户用自然语言描述系统需求，AI 自动完成：需求理解 → 图生成 → 智能审查 → 图片输出。
**不是画图工具，而是教学辅助专家**：既生成图，又像老师一样指出建模错误、讲解为什么错。

**首期支持 3 类图**（均有教材详稿与权威校验表）：

| 图类型 | 用途 | 教材章节 | 校验表 |
|---|---|---|---|
| 用例图 | 需求分析建模 | 任务二（2.3 节） | 边界 / 粒度 / 关系校验表（表 2-4/2-5/2-6） |
| 活动图 | 业务工作流建模 | 任务六（6.x 节） | 泳道 / 动作粒度 / 控制逻辑校验表（表 6-2/6-3/6-4） |
| 状态机图 | 对象状态变迁建模 | 任务七（7.x 节） | 状态与生命周期 / 复合状态与历史状态 / 转换逻辑校验表（表 7-4/7-5/7-6） |

其余图类型（类图/对象图/包图/组件图/时序图/通信图/交互概览图/时间图/部署图/模型驱动开发）列入后续版本（见第 7 节）。

## 2. 用户与场景

| 用户 | 场景 |
|---|---|
| 学生 | 建模作业辅助：描述需求 → 得对应类型的图 + 审查意见 |
| 学生 | 建模训练：故意输入有误需求，看 AI 如何纠正 |
| 教师 | 课堂演示：现场生成 + 讲解建模规范（含四步迭代法演示） |

## 3. 输入输出

**输入**（自然语言需求，可指定图类型）：
- 用例图："设计一个校园二手交易系统。学生可以发布商品，管理员审核商品，买家购买商品。"
- 活动图："绘制 AI 学业预警平台的预警生成与干预推送流程活动图……"
- 状态机图："为'预警信息'对象绘制全生命周期状态机图……"
- 未指定类型时：LLM 意图识别自动判断，或先向用户提问确认。

**输出**：
1. 需求分析结果（按图类型：参与者与用例 / 角色与动作节点 / 状态与转换）；
2. UML 图（PNG，可嵌入 PPT/教案/作业）；
3. 智能审查意见（问题 + 判定标准 + 处理建议，区分"确定错误/建议调整"）；
4. （可选）优化后的图与定向迭代过程记录。

## 4. 处理流程（四步迭代法 · 核心链路）

```
用户自然语言需求（可指定图类型）
  ↓
Step1 需求理解（LLM，按图类型抽取）
  ├─ 用例图：Actor + Use Case + 关系
  ├─ 活动图：参与角色（泳道）+ 动作节点 + 控制逻辑（顺序/分支/并行/跨分区）
  └─ 状态机图：对象 + 状态列表 + 转换关系与触发事件
  ↓
Step2 图生成（中间 JSON → PlantUML 模板渲染）
  ↓
Step3 图片生成（PlantUML → PNG）
  ↓
Step4 智能审查（分图校验规则库 + LLM 复核双重验证）
  ↓
Step5 定向迭代支持（针对问题分条修改指令 → 重生成 → 再审查）
  ↓
最终输出（图 + 审查意见 + 迭代记录）
```

> 对齐教材四步迭代法：Step1 对应"初始提示词"，Step4 对应"系统化质检"，Step5 对应"定向迭代"；"手工前置分析"由学生/教师在建模前完成（辅助实践 PRD 练习模式承接）。

## 5. 分图校验规则库（核心卖点）

> 全部规则来自教材权威校验表，每条含"判定标准 + 不通过时的处理"。

### 5.1 用例图校验（表 2-4/2-5/2-6）

| 校验组 | 检查项 | 判定标准 | 不通过处理 |
|---|---|---|---|
| 边界 | 参与者位置 | 参与者是外部实体，必须画在边界框外 | 移至框外 |
| 边界 | 内部组件误列 | 数据库、扫描引擎等内部模块不属于参与者 | 从参与者列表删除 |
| 边界 | 非人类参与者遗漏 | 定时触发器、外部系统等容易被忽略 | 补充遗漏参与者 |
| 粒度 | 粒度过细 | 用例仅为单一操作步骤（"点击确认按钮"） | 合并至上层用例或删除 |
| 粒度 | 粒度过粗 | 一个用例覆盖多个独立业务目标（"管理漏洞"） | 拆分为多个独立用例 |
| 关系 | 包含关系 | 基础用例执行时被包含用例必须被执行 | 删除测试验证 |
| 关系 | 扩展关系 | 扩展用例仅在特定条件满足时才执行 | 提问"每个场景都必须执行吗" |
| 关系 | 泛化关系 | 子用例继承父用例行为并扩展自身特有行为 | 检查行为继承 |

### 5.2 活动图校验（表 6-2/6-3/6-4）

| 校验组 | 检查项 | 判定标准 | 不通过处理 |
|---|---|---|---|
| 泳道分区 | 分区完备 | 每个责任主体应有对应泳道 | 补充遗漏分区 |
| 泳道分区 | 节点归属 | 每个动作节点放所属责任主体分区内 | 移至正确分区 |
| 泳道分区 | 内部组件误列 | 数据库、消息队列等内部组件不属于泳道 | 删除或调整为对象节点 |
| 泳道分区 | 跨分区控制流 | 使用带箭头的实线表示 | 检查连接线正确性 |
| 动作粒度 | 粒度过细 | 动作为单一界面操作（"点击确认按钮"） | 合并或删除 |
| 动作粒度 | 粒度过粗 | 一个动作覆盖多个独立业务步骤（"完成预警全流程"） | 拆分为多个动作节点 |
| 动作粒度 | 遗漏关键动作 | 流程描述有明确步骤但图中缺失 | 补充动作节点 |
| 控制逻辑 | 顺序流转 | 相邻动作有明确先后依赖，无孤立节点 | 补连接/删除孤立节点 |
| 控制逻辑 | 条件分支 | 决策节点各输出分支标注互斥监护条件，含"[else]"兜底 | 补监护条件/兜底 |
| 控制逻辑 | 分支汇合 | 决策节点与合并节点配套，覆盖所有输出分支 | 补配套/覆盖 |
| 控制逻辑 | 并行分叉/同步 | 分叉输出数=汇合输入数，各并行分支均连至汇合节点 | 对齐分支数量 |
| 控制逻辑 | 数据传递 | 对象节点连接在正确产出/消费动作之间，命名"对象名:类型名" | 修正连接与命名 |

### 5.3 状态机图校验（表 7-4/7-5/7-6）

| 校验组 | 检查项 | 判定标准 | 不通过处理 |
|---|---|---|---|
| 状态与生命周期 | 核心对象明确 | 围绕单一反应型对象构建 | 标注对象名称 |
| 状态与生命周期 | 生命周期覆盖 | 从创建覆盖至销毁/归档，无遗漏阶段 | 补充遗漏状态（异常/暂停等） |
| 状态与生命周期 | 粒度过细 | 状态是稳定阶段，不与动作节点混淆（"正在执行XX"是动作） | 合并或调整为复合状态子状态 |
| 状态与生命周期 | 初始/最终状态 | 一个初始伪状态（●）、至少一个最终状态（◉） | 补齐 |
| 复合/历史状态 | 顺序 vs 并发 | 有先后依赖用顺序复合状态；独立可并行用并发复合状态 | 调整复合状态类型 |
| 复合/历史状态 | 并发区域完备 | 每个并发区域有独立初始/最终伪状态 | 补充 |
| 复合/历史状态 | 历史状态误用/遗漏 | 中断恢复需记忆位置用浅历史（H），多层嵌套用深历史（H*） | 添加/移除历史状态 |
| 转换逻辑 | 事件触发完整性 | 每个转换均有明确触发事件，无"无源触发"转换 | 标注触发事件 |
| 转换逻辑 | 监护条件正确性 | 布尔表达式，同一事件多转换的监护条件互斥 | 修正/补充监护条件 |
| 转换逻辑 | 动作标注规范 | "事件触发 [监护条件] / 动作"格式 | 修正标注 |
| 转换逻辑 | 转换目标合法性 | 转换终点均为已定义状态，无悬空转换 | 核对并修正 |

### 5.4 双重验证（贯穿三类图）

- 第一重：规则校验（上述分图规则引擎，确定性代码）；
- 第二重：LLM 复核（对规则通过的模型做整体合理性判断）；
- 两层都通过才输出"已通过审查"；任一失败给出问题清单 + 修改建议。

## 6. 功能需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| UML-1 | 图类型识别 | 未指定时正确识别/确认用例图/活动图/状态机图 |
| UML-2 | 需求理解 | 按图类型正确抽取模型元素（Actor/UseCase、泳道/动作、状态/转换） |
| UML-3 | 图生成 | 产出中间 JSON 与 PlantUML，模板渲染确定可复现 |
| UML-4 | 图片输出 | 生成 PNG，可下载 |
| UML-5 | 分图校验 | 三类图各自按校验规则库检查（边界/粒度/关系、泳道/粒度/控制逻辑、状态/复合状态/转换逻辑） |
| UML-6 | 双重验证 | 规则 + LLM 复核两层，故意错误用例能被拦截 |
| UML-7 | 定向迭代 | 支持分条修改指令 → 重生成 → 再校验的迭代闭环 |
| UML-8 | 教学反馈 | 每条审查意见含"判定标准 + 为什么错 + 怎么改" |
| UML-9 | 校验表对照 | 审查意见可对照教材表号（表 2-4/6-2/7-4 等），便于学生回教材学习 |

## 7. 边界与例外

- **首期支持**：用例图 / 活动图 / 状态机图（均有教材详稿与权威校验表）；
- **后续版本**：类图、对象图、包图与组件图、时序图与通信图、交互概览图与时间图、部署图、模型驱动开发（互动点已登记在辅助实践 PRD 全景表）；
- 需求信息不足时，先向用户提问补全（启发思考，见辅助实践 PRD）；
- 生成的图为教学辅助，最终以教师审阅为准；
- PlantUML 服务不可用时，降级输出 PlantUML 源码（不阻塞演示）。

## 8. 验收标准

- 三类图（用例图/活动图/状态机图）主流程可演示、可复现；
- UML 评测集（含三类图，见测试规范第 3 节）通过率 ≥ 90%；
- 三类图各自的典型错误用例（如数据库当参与者、动作粒度过细、悬空转换）能按规则拦截；
- 从需求输入到出图 ≤ 30s；
- 双重验证机制可演示（故意输入错误 → AI 拦截并讲解）；
- 审查意见可对照教材校验表号，教学反馈含"标准 + 原因 + 改法"。
