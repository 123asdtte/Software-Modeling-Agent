## 2. 分层职责

| 层 | 职责 | 关键组件 |
|---|---|---|
| 用户端 | 展示与交互 | 演示 Web 页 / 教学平台 |
| API 层 | 统一入口、鉴权、限流、参数校验 | FastAPI `app/main.py` |
| 调度层 | 意图路由、多 Agent 编排、状态管理 | LangGraph Supervisor |
| Agent 层 | 各业务能力 | qa / ppt / lesson / uml 四 Agent |
| 链层 | 可复用流程 | rag_chain / uml_chain / generation_chain |
| 工具层 | 外部能力封装 | plantuml_tool / ppt_generator / document_reader |
| 知识层 | 教材入库与检索 | RAG + Vector DB |
| 模型层 | 大模型统一访问 | `app/models/llm.py` |
| 存储层 | 会话/练习记录 | SQLite / PostgreSQL |

## 3. 数据流（以 UML 建模为例）

```
用户请求（自然语言，可指定图类型）
 → FastAPI 鉴权/校验
 → LangGraph 路由（识别为 UML 建模 + 图类型）
 → uml_agent 子图：
    图类型识别 → 需求理解 → 中间 JSON → PlantUML 源码 → 图片
    → 分图规则质检（用例图/活动图/状态机图校验规则库）
    → LLM 复核（双重验证）
    → 定向迭代（分条修改指令 → 重生成 → 再审查）
    → 组装输出（图 + 审查报告 + 迭代记录）
 → FastAPI 返回 JSON（图 URL + 报告）
 → Web 展示
```

## 4. 多 Agent 调度设计

- **意图识别**：入口先用 LLM 分类（问答 / PPT / 教案 / UML / 其他），分类置信度低时返回选项让用户确认；
- **Supervisor 图**：LangGraph 中定义路由节点 + 各子图；每步状态可记录、可回放；
- **会话状态**：同一会话内支持追问（问答 3 轮、UML 需求补全）；
- **失败处理**：子图异常返回兜底消息，不中断整个请求。

## 5. RAG 知识库架构

```
教材/课程资料（Word / PDF / MD）
  → document_reader 解析
  → 语义分块（保留章节元数据）
  → Embedding 向量化
  → Vector DB 索引（FAISS）
  → 查询：问题向量化 → top-k 召回 → 重排 → 上下文
```

详见 `03_RAG知识库设计方案.md`。

## 7. 架构决策记录（ADR）

| # | 决策 | 理由 | 备选 |
|---|---|---|---|
| 1 | FastAPI 做 API 层 | 异步、自带文档、生态好 | Flask |
| 2 | LangGraph 做调度 | 多 Agent 状态编排、可回放 | 纯 Chain |
| 3 | 模型走工厂 | 一处切换 DeepSeek/兼容模型 | 直接调用 |
| 4 | RAG 向量 + 元数据 | 回答可溯源 | 纯向量 |
| 5 | PlantUML 本地渲染 | 离线、稳定出图 | Draw.io |
