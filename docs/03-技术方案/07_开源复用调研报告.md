# 开源复用调研报告（v13）

> 目的：调研 GitHub 开源生态，为 v13 各模块寻找可复用轮子，避免重复造轮子，明确"直接复用 / 参考改造 / 必须自研"三类边界。
> 调研时间：2026-09-21。Star 数为公开数据，随社区变化，供选型参考。

---

## 1. 调研结论（一句话）

没有任何一个开源项目能完整替代 v13（"UML 多图类型智能审查 + 教材 43 个 AI 互动点 + 教学场景集成"的组合是独有的），但**五大功能模块全部有成熟开源方案可借**，知识库、PPT 生成、UML 生成的底层能力不必从零实现；v13 的核心工作量应集中在智能审查与教学场景集成这一差异化层。

## 2. 分模块开源方案明细

### 2.1 智能问答 Agent（RAG 知识库）

| 项目 | Star 量级 | 简介 | 许可 | 建议 |
|---|---|---|---|---|
| **QAnything**（netease-youdao） | 14k+ | 网易有道开源本地知识库问答，基于自研教育大模型（子曰）的 RAG 引擎，多格式文档、离线可部署 | 开源 | **可直接复用**：作为知识库问答底座或参考其检索链路 |
| **MaxKB**（飞致云） | 22k+ | 企业级 AI 助手，内置 RAG、工作流编排、MCP 工具调用，支持主流大模型 | GPL v3 | **可直接复用**：自带 Web 界面，可快速搭建校内知识库 |
| **RAGFlow**（InfiniFlow） | — | 深度文档理解型 RAG 引擎，复杂 PDF 解析能力强，支持 Agent 应用发布 | Apache 2.0 | **参考改造**：教材 PDF 解析质量要求高时采用其解析管线 |
| **LightRAG**（HKUDS 港大） | — | 轻量级 RAG 框架，FastAPI + Embedding + 向量库，部署简单 | 开源 | **参考改造**：轻量接入教学场景，替换自建检索代码 |

**对 v13 的意义**：`03-技术方案/03_RAG知识库设计方案.md` 中"文档解析 → 分块 → 向量化 → 检索"链路可整体借鉴上述引擎的成熟实现，或直接以 QAnything / RAGFlow 为底座，保留 FAISS 轻量方案用于 Demo。

### 2.2 PPT 生成 Agent

| 项目 | Star 量级 | 简介 | 许可 | 建议 |
|---|---|---|---|---|
| **PPT Master**（Hugo He） | 30k+ | 从 PDF/DOCX/URL/MD 生成**原生可编辑 PPTX**（真实文本框、形状、母版），支持自定义模板、讲者备注转语音；以 Skill 工作流形态在 AI IDE 中运行 | MIT | **直接封装**：与 v13 "生成 PPT 文件 + 讲课备注"需求高度吻合 |
| **Presenton** | — | 开源 AI 演示文稿生成器，支持 PPTX/PDF 导出、OpenAI/Gemini/Ollama 本地模型 | 开源 | **参考改造**：本地模型通道与 v13 内网部署场景契合 |

**对 v13 的意义**：PPT 生成统一采用 **python-pptx 输出原生可编辑 .pptx**（与 `01_技术选型方案.md` 一致），工作流设计直接参考 PPT Master：大纲规划 → 分页生成 → 原生元素组装 → 讲者备注。PPT Master 本身即"Skill 封装"的典型范例。

### 2.3 教案生成 Agent

| 项目 | Star 量级 | 简介 | 许可 | 建议 |
|---|---|---|---|---|
| **Claw-ED**（clawed） | — | 教师专用开源 CLI Agent，生成完整教案包（教案 + 讲义 + 幻灯片 + 差异化版本 + 评估），"Made by a teacher, for teachers"，含学生端 Claw-STU | 开源 | **直接借鉴**：教案结构、Prompt 设计、输出格式可直接套用 |
| **OpenMAIC**（THU-MAIC 清华） | 29.6k+ | 开源多智能体互动课堂平台，LangGraph 两阶段流水线，含"课程规划器 Agent"：分析文档/主题 → 生成结构化课程大纲与教案 | MIT | **参考架构**：课程规划器即教案生成 Agent 的成熟实现 |

**对 v13 的意义**：教案生成 Agent 的"目标/重点难点/流程/师生活动/练习/作业"结构在开源社区已有成熟 Prompt 设计，无需从零摸索；OpenMAIC 的规划 Agent 模式还可整体借鉴。

### 2.4 UML 智能建模 Agent（核心）

| 项目 | Star 量级 | 简介 | 许可 | 建议 |
|---|---|---|---|---|
| **PlantUML** | 12.5k+ | 文本 → UML 渲染，支持全部 14 类 UML 图，LLM 对其语法掌握成熟 | MIT | **直接复用**：v13 技术方案已选定，本地 jar 离线渲染 |
| **uml-mcp**（antoinebou12） | — | MCP Server：自然语言/代码 → UML/Mermaid/D2，PlantUML + Kroki 后端，安全评分低风险 | 开源 | **直接封装为 Tool**：LangGraph Agent 通过 MCP 协议挂载 |
| **code-to-uml**（npm） | — | 自带 `SKILL.md` 定义，AI 编码助手（Cursor/Claude Code 等）即装即用，生成分析报告 | 开源 | **直接封装**：Skill 形态的 UML 生成能力 |
| **UML-MCP-Server / UML Forge / GitUML** | — | MCP 生态 UML 生成：多图类型、本地保存、C4 架构图等 | 开源 | **参考**：按需挂载多种图类型 |

**对 v13 的意义（重点）**：
- **生成层**（自然语言 → 中间 JSON → PlantUML → 图片）全部有现成轮子，`uml-mcp` 或 `code-to-uml` 可直接作为 Agent Tool 封装，不必自写 PlantUML 转换与渲染；
- **审查层**（边界检查 / 粒度检查 / 关系判断 / 双重验证）在开源社区**没有对应实现**——这正是 v13 区别于"画图工具"的差异化护城河，必须自研。

## 3. 可封装 Skill / Tool 清单（直接进智能体的能力）

当前业界 Agent 能力封装有三种形态，v13 均可采用：

| 封装形态 | 代表项目 | 接入方式 | v13 落地位置 |
|---|---|---|---|
| **MCP Server** | uml-mcp、UML-MCP-Server、GitUML | Agent 通过 MCP 协议调用，作为 Tool 挂载 | UML Agent 的图生成 Tool |
| **Skill 定义**（SKILL.md） | code-to-uml、PPT Master、plantuml-skill | 作为 Agent 的可复用技能包加载 | PPT Agent、UML Agent |
| **库 / API** | PlantUML、python-pptx、QAnything / RAGFlow | 作为底层依赖或服务调用 | 渲染层、知识库层 |

## 4. 复用策略汇总

| 模块 | 策略 | 具体做法 |
|---|---|---|
| 智能问答 | **接现成引擎** | 底座选 QAnything / RAGFlow（或参考其管线），FAISS 留作 Demo 轻量方案 |
| PPT 生成 | **封装现成工作流** | python-pptx + PPT Master 工作流思路，输出原生可编辑文件 |
| 教案生成 | **借鉴现成结构** | Claw-ED 教案结构 + OpenMAIC 课程规划器 Prompt |
| UML 生成 | **挂载现成 Tool** | 封装 uml-mcp / code-to-uml，PlantUML 本地渲染 |
| UML 审查 | **必须自研** | 分图校验规则引擎（用例图/活动图/状态机图）+ LLM 复核双重验证（教材 43 个 AI 互动点） |
| 编排层 | **沿用框架** | LangGraph supervisor 路由，参考 OpenMAIC 两阶段设计 |

## 5. 自研边界（差异化护城河）

以下内容无现成开源方案，为 v13 必须自研、也是对外汇报的核心价值：

1. **UML 智能审查**：系统边界（数据库不是 Actor）、用例粒度（"点击按钮"是操作不是业务目标）、参与者—用例关系、include/extend 关系判断；
2. **综合建模双重验证**：规则校验 + 大模型复核；
3. **教材 43 个 AI 互动点**：启发思考、审查校验（边界/粒度/命名/完整性/覆盖率）、关系语义辨析（删除测试等）、综合验证模拟（双重验证等）——需与学校教材内容深度绑定；
4. **教学场景集成**：面向师生的一体化流程（备课 → 授课 → 学生训练 → 作业反馈）。

## 6. 待确认事项

| 事项 | 影响 | 决策方 |
|---|---|---|
| 知识库底座选"接现成引擎"还是"自建轻量 RAG" | 影响开发量与演示效果 | 技术负责人 + 陈老师 |
| 是否引入 MCP 依赖（uml-mcp 等） | 影响部署复杂度与内网可用性 | 技术负责人 |
| PPT Master 为 Skill 工作流形态，需确认运行环境（AI IDE）是否与 v13 架构兼容 | 影响 PPT 模块实现方式 | 技术负责人 |
