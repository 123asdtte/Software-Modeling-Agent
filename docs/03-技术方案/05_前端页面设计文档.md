# M5 前端页面设计文档（功能需求规格书）

> 版本：v2.0 ｜ 日期：2026-09-23 ｜ 状态：待原型实现
>
> **本文档只规定「做什么功能」，不规定「长什么样」。**
> 视觉风格、页面布局、配色字体、组件形态完全由实现者自由发挥——请把它当作展示你设计能力的作品。
> 唯一的硬约束是：纯 HTML/CSS/JS 实现、对接本文档第 4 节的真实 API、满足第 5 节的安全要求。

---

## 1. 项目背景

「AI 教学智能体平台」是面向**高职软件建模课程教师**的辅助教学系统，后端为 FastAPI（本仓库 `app/`），已具备四项真实可用的能力：

| 能力 | 后端端点 | 说明 |
|---|---|---|
| 教材智能问答（RAG） | `POST /v1/qa` | 基于教材知识库回答，四段式结构 + 教材来源引用 |
| UML 用例图建模 | `POST /v1/uml/usecase` | 一句需求 → 结构化模型 + PlantUML 源码 + PNG/SVG 图片 + 规则质检报告 |
| PPT 生成 | `POST /v1/ppt` | 课题 + 课时 → 大纲 + 分页内容 + .pptx 下载 |
| 教案生成 | `POST /v1/lesson` | 课题 + 课时 → 9 字段教学设计 + docx 下载 |

**目标用户**：高职软件建模课程的授课教师（备课/做课件/课堂演示）。
**使用场景**：教师机浏览器直接访问本机 FastAPI 服务，全中文界面。

---

## 2. 技术约束（硬性）

1. **纯 HTML / CSS / 原生 JavaScript（ES2020+）**：禁止构建工具（Vite/Webpack）、框架（Vue/React）、npm 依赖、第三方 CDN（演示机可能无外网，一切资源本地化或内联）。
2. **同源部署**：前端由 FastAPI 挂载在 `/static` 下（`GET /` 返回首页）。所有 API 调用使用**相对路径**（如 `fetch("/v1/qa")`），禁止硬编码 `http://host:port`。
3. **目录与命名自由**：文件如何组织、CSS 如何拆分由你决定；唯一要求是入口为 `index.html`，且另外三页可从导航到达。建议命名 `uml.html / qa.html / resources.html`（与后端测试兼容）。
4. **浏览器目标**：Chrome/Edge 最新两个大版本（教师机 Windows），无需兼容 IE。
5. **禁止**：`eval`/`exec`、把服务端返回的文本用 `innerHTML` 未转义拼接（XSS，见第 5 节）。

## 3. 页面与功能需求

四个页面，导航互通。每页列出**必须实现的功能点**——如何呈现、如何布局由你设计。

### 3.1 首页（index.html）

平台门面，让观看者 3 秒内明白平台是什么、能做什么，并引导进入各功能页。

- [ ] 展示平台名称与四项能力的入口（点击可达对应页面）
- [ ] 顶部/全局导航：四个页面互相可达，当前页有标识
- [ ] 展示服务健康状态（`GET /health`，建议 30s 轮询一次；仅影响一个状态标识，失败不阻塞页面）

### 3.2 UML 建模页（uml.html）——功能最完整的一条链路

教师输入一句自然语言需求，系统返回：结构化模型、PlantUML 源码、渲染图片（或降级说明）、质检报告。

- [ ] 需求输入框（1~3000 字，带字数统计与超限提示；为空提交时给出非阻断提示）
- [ ] 图片格式选择：PNG / SVG（默认 PNG）
- [ ] 「生成」动作：调用 `POST /v1/uml/usecase`（超时建议 180s；请求期间按钮禁用 + 明确的进行中反馈）
- [ ] 生成结果展示，必须覆盖两种分支：
  - `render.status === "rendered"`：显示图片（`render.download_url` 指向的图片）+ 图片下载
  - `render.status === "source_only"`：不显示图片，改为展示 `render.reason` 的说明——**此时源码和质检报告仍须完整展示**
- [ ] 质检报告展示：`review_report.passed` 总体结论 + `issues` 列表（每条含 `level` 徽章 / `rule_id` / `target` / `message` / `suggestion`）
- [ ] PlantUML 源码展示（等宽字体）+ 复制到剪贴板
- [ ] 结构化模型（`model`）的参与者和用例可以简单展示（展示方式自由）
- [ ] 示例需求快捷填入（至少 3 条，内容自拟，如"学生可以发布商品，管理员审核商品"）
- [ ] 失败处理：502 / 504 / 网络错误各自有友好文案，输入保留可重试，不暴露堆栈或内部 JSON

### 3.3 教材智能问答页（qa.html）

教师/学生基于教材知识库提问，得到四段式回答 + 来源引用。

- [ ] 提问输入（1~1000 字）+ 提交动作（调用 `POST /v1/qa`，超时建议 120s）
- [ ] 回答展示：`reply` 为纯文本，`【概念解释】`等段落标题开头按换行分段
- [ ] 教材来源展示：`sources` 列表（文件名 + snippet 摘要），默认收起或弱化展示均可
- [ ] 示例问题快捷填入（至少 4 条，内容自拟）
- [ ] 多轮会话：页面内保留历史消息（仅内存即可，刷新清空可接受），最新提问滚动可见
- [ ] 失败处理同上

### 3.4 课件与教案生成页（resources.html）

Tab 或其他形式切换两种生成能力，各自独立表单与结果区。

**PPT 生成**（`POST /v1/ppt`，超时建议 180s）：

- [ ] 输入：课题（2~100 字）+ 课时（15~240 分钟，默认 90）
- [ ] 结果展示：`title`、总页数（`total_pages`）、大纲（`outline.sections`：名称 + 页数 + 要点）、逐页内容预览（`pages`：标题 + bullets + 备注）
- [ ] `.pptx` 下载（`download_url`）

**教案生成**（`POST /v1/lesson`，超时建议 180s）：

- [ ] 输入：课题 + 课时（默认 45）
- [ ] 结果展示（`lesson` 结构化字段）：课程名、教学目标（知识/能力/素养三组）、重点、难点、教学流程表（环节/分钟/教师活动/学生活动）、课堂练习、课后任务
- [ ] `.docx` 下载（`download_url`）
- [ ] `missing_fields` 非空时提示教师部分字段缺失
- [ ] **必须**有明显提示：生成内容为 AI 生成，请教师审核后使用

两类生成共通：

- [ ] 失败处理：502 / 504 / 网络错误友好文案；输入保留可重试
- [ ] `POST /v1/ppt` 或 `/v1/lesson` 返回非 200 属正常容错场景（模型供应商偶发超时），展示友好提示即可

## 4. API 契约（唯一接口文档，字段名不可更改）

所有 POST 请求 `Content-Type: application/json`。下载直接使用响应里的 `download_url`（相对路径），不需要额外接口。

### 4.1 服务健康

```text
GET /health → 200 {"status": "ok"}
```

### 4.2 教材智能问答

```text
POST /v1/qa
请求：{"question": "什么是用例图？"}                  // 1~1000 字
200：
{
  "reply": "【概念解释】…【通俗案例】…【教材关联】…【任务定位】…",
  "sources": [
    {"source": "AI辅助生成用例图.md", "snippet": "用例图用于需求分析建模…"}
  ]
}
错误：422（参数有误）/ 502（模型失败，detail 为友好文案）/ 504（超时）
```

### 4.3 UML 用例图建模

```text
POST /v1/uml/usecase
请求：
{
  "requirement": "学生可以发布商品，管理员审核商品",   // 1~3000 字，必填
  "render": true,                                     // 可选，默认 true
  "format": "png"                                     // 可选，"png"|"svg"，默认 "png"
}
200：
{
  "diagram_type": "usecase",
  "model": {
    "type": "usecase",
    "system": "校园二手交易系统",
    "actors": [{"name": "学生", "role": "primary"}],
    "usecases": [{"id": "UC-01", "name": "发布商品", "actors": ["学生"], "goal": ""}],
    "relations": [{"type": "include", "from": "UC-02", "to": "UC-01", "note": ""}]
  },
  "plantuml": "@startuml\nleft to right direction\n…\n@enduml",
  "review_report": {
    "passed": true,
    "issues": [
      {"rule_id": "UC-G1", "level": "warning", "target": "UC-03",
       "message": "用例名含界面操作词…", "rule_group": "粒度校验",
       "suggestion": "建议改为表达业务目标的名称", "table_ref": ""}
    ]
  },
  "render": {
    "status": "rendered",          // "rendered" | "source_only"
    "format": "png",               // rendered 时为 "png"|"svg"；source_only 时 null
    "download_url": "/files/uml/<uuid>.png",   // source_only 时 null
    "reason": null                 // source_only 时的原因
  }
}
错误：422 / 502 / 504（>180s）
```

### 4.4 PPT 生成

```text
POST /v1/ppt
请求：{"topic": "软件工程 UML 建模", "minutes": 45}   // topic 2~100 字；minutes 15~240
200：
{
  "title": "用例图建模入门",
  "total_pages": 9,
  "outline": {"title": "...", "subtitle": "...",
              "sections": [{"name": "课程导入", "page_count": 1, "points": ["…"]}]},
  "pages": [{"title": "课程目标", "bullets": ["…"], "note": "讲解要点", "minutes": 5}],
  "download_url": "/files/ppt/<uuid>.pptx"
}
错误：422 / 502 / 504
```

### 4.5 教案生成

```text
POST /v1/lesson
请求：{"topic": "用例图教学设计", "minutes": 45}
200：
{
  "lesson": {
    "course_name": "用例图教学设计",
    "teaching_goals": {"knowledge": ["…"], "ability": ["…"], "literacy": ["…"]},
    "key_points": ["…"], "difficult_points": ["…"],
    "teaching_flow": [{"stage": "导入", "minutes": 5, "teacher_activity": "…", "student_activity": "…"}],
    "class_exercises": ["…"], "homework": ["…"]
  },
  "markdown": "# 用例图教学设计\n> AI 生成，请教师审核后使用\n…",
  "missing_fields": [],
  "download_url": "/files/lesson/<uuid>.docx"

错误：422 / 502 / 504
```

### 4.6 文件下载

```text
GET /files/uml/{filename}    → image/png | image/svg+xml
GET /files/ppt/{filename}    → .pptx
GET /files/lesson/{filename} → .docx
404 = 文件不存在（不应发生，除非用户手动篡改 URL）
```

## 5. 通用交互要求（功能性，非视觉性）

| 场景 | 要求 |
|---|---|
| 请求进行中 | 触发按钮禁用 + 用户可感知的进行中反馈（形式自由：进度条/动画/文案均可） |
| 超时 | 各页按上述建议值设超时；超时文案「请求超时，请稍后重试」 |
| 失败 | 友好文案来自响应 `detail`（502）或固定文案；**禁止**展示堆栈、内部 JSON、绝对路径 |
| 空输入提交 | 非阻断提示（如输入框标红 + 文案），不得弹出原生 alert |
| 文本插入 | 所有服务端文本必须转义或用 `textContent` 插入（XSS 防护，硬性） |
| 防重复提交 | 请求进行中重复点击无效 |

## 6. 验收标准

- [ ] 四页导航互通，`GET /` 可进入
- [ ] UML 页完整链路：需求 → 图片（或 source_only 说明）→ 质检报告 → 源码复制 → 图片下载
- [ ] QA 页：提问 → 四段式回答 → 来源展示；示例问题可用
- [ ] 资源页：PPT 与教案均可生成、预览、下载；教案有审核提示；`missing_fields` 提示生效
- [ ] 全部错误态友好、无内部信息泄露；全部动态文本转义插入
- [ ] 无任何第三方 CDN / npm 依赖 / 构建工具
- [ ] 1280×800 与 1920×1080 下布局不破版
- [ ] 控制台无 JS 报错

## 7. 设计自由度声明（给实现者）

以下是**完全由你决定**的部分，请大胆按自己的审美与理解设计：

- 视觉风格（配色、字体、圆角、阴影、动效、明暗）
- 页面布局与信息层级（单栏/双栏/卡片/分步向导均可）
- 组件形态（按钮/徽章/表格/对话气泡的具体样子）
- CSS 组织方式（拆几个文件、用什么命名法均可）
- 加载反馈与微交互的具体形式

只有三件事不可妥协：**第 2 节的技术约束、第 4 节的 API 字段、第 5 节的安全要求。**
