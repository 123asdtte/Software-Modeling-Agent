## 1. 项目背景与目标用户

「AI 教学智能体平台」是面向**高职软件建模课程教师**的辅助教学系统，后端为 FastAPI（本仓库 `app/`），已具备四项能力：

| 能力 | 后端端点 | 说明 |
|---|---|---|
| 教材智能问答（RAG） | `POST /v1/qa` | 基于教材知识库回答，四段式结构 + 来源引用 |
| PPT 生成 | `POST /v1/ppt` | 课题 → 大纲 + 分页内容 + .pptx 下载 |
| 教案生成 | `POST /v1/lesson` | 课题 → 9 字段教学设计 + docx 下载 |
| UML 用例图建模 | `POST /v1/uml/usecase` | 需求 → 结构化模型 + PlantUML 源码 + PNG/SVG 图片 + 规则质检报告 |

**目标用户**：授课教师（备课/出题/做课件）、教学检查（规范教案）、课程演示（公开课/评审）。
**使用场景**：教师机浏览器直接访问本机 FastAPI 服务，全中文界面。

## 2. 技术约束（硬性，违反即返工）

1. **纯 HTML / CSS / 原生 JavaScript（ES2020+）**：禁止任何构建工具（Vite/Webpack）、框架（Vue/React）、npm 依赖。
2. **无后端改动**：所有页面只消费本文档第 5 节的既有 API；不得要求后端新增字段。
3. **同源部署**：前端由 FastAPI 静态挂载（后端将挂载 `static/` 目录到 `/static`，并让 `GET /` 返回 `static/index.html`）。前端代码**不允许硬编码 `http://host:port`**，一律使用相对路径（如 `fetch("/v1/qa")`）。
4. **文件结构**（锁定）：
   ```text
   static/
   ├── index.html          # Demo 首页
   ├── uml.html            # UML 建模页
   ├── qa.html             # 教材智能问答页
   ├── resources.html      # PPT/教案生成页（双 Tab）
   ├── css/
   │   ├── tokens.css      # 设计 token（第 4 节，唯一色彩/字体/间距来源）
   │   └── main.css        # 布局与组件样式（引用 tokens.css）
   └── js/
       ├── api.js          # 统一 API 封装（见 5.6）
       ├── layout.js       # 顶栏导航渲染（每页引入）
       ├── uml.js          # UML 页逻辑
       ├── qa.js           # QA 页逻辑
       └── resources.js    # 资源生成页逻辑
   ```
5. **浏览器目标**：Chrome/Edge 最新两个大版本（教师机 Windows），无需兼容 IE。
6. **禁止**：`eval`/`exec` 等价物、内联事件以外的 `document.write`、第三方 CDN 依赖（演示机可能无外网，一切资源本地化）。

## 4. 设计系统（Design Tokens）

**风格关键词**：克制的、栅格化的、企业 SaaS、单一品牌色、无渐变无炫彩、大量留白。

### 4.1 色彩 token（写入 `tokens.css` 的 CSS 变量）

| Token | 值 | 用途 |
|---|---|---|
| `--color-primary` | `#1a56db` | 主色：按钮、链接、选中态、品牌区 |
| `--color-primary-hover` | `#1e429f` | 主按钮悬停 |
| `--color-primary-light` | `#e1effe` | 主色浅底（选中 Tab 背景、信息提示条） |
| `--color-bg` | `#f9fafb` | 页面背景 |
| `--color-surface` | `#ffffff` | 卡片/面板背景 |
| `--color-border` | `#e5e7eb` | 边框、分隔线 |
| `--color-text` | `#111827` | 主文字 |
| `--color-text-secondary` | `#6b7280` | 次要文字、说明 |
| `--color-success` | `#16a34a` | 成功态、质检通过徽章 |
| `--color-success-light` | `#ecfdf5` | 成功浅底 |
| `--color-warning` | `#d97706` | 警告徽章（质检 warning） |
| `--color-warning-light` | `#fffbeb` | 警告浅底 |
| `--color-error` | `#dc2626` | 错误徽章（质检 error）、错误提示 |
| `--color-error-light` | `#fef2f2` | 错误浅底 |
| `--color-info` | `#0284c7` | 信息徽章（质检 info） |
| `--color-info-light` | `#f0f9ff` | 信息浅底 |

### 4.2 字体与字号

| Token | 值 |
|---|---|
| `--font-family` | `system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif` |
| `--font-mono` | `Consolas, "Courier New", monospace`（PlantUML 源码展示用） |
| 字号 | 页面标题 20px/600；卡片标题 16px/600；正文 14px/400；辅助文字 12px/400；行高 1.6 |

### 4.3 间距 / 圆角 / 阴影

| Token | 值 |
|---|---|
| 间距 | 4px 基数：4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 卡片 `--radius-card: 8px`；按钮/输入框 `--radius-input: 6px`；徽章 `999px` |
| 阴影 | 卡片 `0 1px 3px rgba(0,0,0,.1)`；悬浮面板 `0 4px 12px rgba(0,0,0,.08)` |
| 主容器 | `max-width: 1080px; margin: 0 auto; padding: 24px 16px` |

### 4.4 核心组件规范

- **按钮**：主按钮（primary 底白字）、次按钮（白底灰边）、禁用态（40% 透明 + `cursor: not-allowed`）。高度 36px，内边距 0 16px。生成类按钮在请求期间必须变为禁用并显示「生成中…」。
- **输入框/文本域**：白底、`--color-border` 边框、focus 时边框变 `--color-primary` + 外发光 `0 0 0 3px rgba(26,86,219,.15)`。错误时边框 `--color-error`。
- **卡片**：白底、圆角 8px、轻阴影、内边距 24px。
- **徽章**：圆角胶囊，浅底深字（如质检 error = `--color-error-light` 底 + `--color-error` 字）。
- **Tab**：下划线式（选中项底部 2px `--color-primary`，文字变主色）。

## 5. API 契约（前后端唯一接口文档）

所有请求 `Content-Type: application/json`（下载链接除外）。所有列表页面的错误处理见 6.3。

### 5.1 服务健康

```text
GET /health → 200 {"status": "ok"}
```
顶栏状态点每 30 秒调用一次；非 200 显示红色。

### 5.2 教材智能问答

```text
POST /v1/qa
请求：{"question": "什么是用例图？"}          // 1~1000 字
成功 200：
{
  "reply": "【概念解释】…【通俗案例】…【教材关联】…【任务定位】…",
  "sources": [
    {"source": "AI辅助生成用例图.md", "snippet": "用例图用于需求分析建模…"}
  ]
}
错误：422（问题为空/超长）、502（模型失败，detail 为友好文案）、504（超时）
```
`reply` 为纯文本，四段式以 `【概念解释】` 等段落标题开头，前端按换行分段渲染即可，**不要**自行解析段落标题做样式（保持简单）。

### 5.3 UML 用例图建模

```text
POST /v1/uml/usecase
请求：{"requirement": "学生可以发布商品，管理员审核商品", "render": true, "format": "png"}
      // requirement 1~3000 字；render 默认 true；format 可选 "png"|"svg"，默认 "png"
成功 200：
{
  "diagram_type": "usecase",
  "model": { "type": "usecase", "system": "校园二手交易系统",
             "actors": [{"name": "学生", "role": "primary"}],
             "usecases": [{"id": "UC-01", "name": "发布商品", "actors": ["学生"], "goal": ""}],
             "relations": [{"type": "include", "from": "UC-02", "to": "UC-01", "note": ""}] },
  "plantuml": "@startuml\nleft to right direction\n…\n@enduml",
  "review_report": {
    "passed": true,
    "issues": [
      {"rule_id": "UC-G1", "level": "warning", "target": "UC-03",
       "message": "用例名含界面操作词…", "rule_group": "粒度校验",
       "suggestion": "…", "table_ref": ""}
    ]
  },
  "render": {
    "status": "rendered",            // "rendered" 或 "source_only"
    "format": "png",                 // rendered 时为 "png"|"svg"；source_only 时为 null
    "download_url": "/files/uml/<uuid>.png",   // source_only 时为 null
    "reason": null                   // source_only 时的原因说明
  }
}
错误：422（需求为空/超 3000 字）、502（模型失败）、504（超时，>150s）
```

### 5.4 图片与文件下载

```text
GET /files/uml/{filename}    → 200 image/png | image/svg+xml（404 = 文件不存在）
GET /files/ppt/{filename}    → 200 (.pptx)
GET /files/lesson/{filename} → 200 (.docx)
```
前端直接 `<img src="/files/uml/xxx.png">` 或 `<a href="..." download>` 使用 `download_url`，**不需要**再调用其他接口。

### 5.5 PPT 生成

```text
POST /v1/ppt
请求：{"topic": "软件工程 UML 建模", "minutes": 45}   // topic 2~100 字；minutes 15~240，默认 90
成功 200：
{
  "title": "用例图建模入门",
  "total_pages": 9,
  "outline": {"title": "...", "subtitle": "...",
              "sections": [{"name": "课程导入", "page_count": 1, "points": ["…"]}, …]},
  "pages": [
    {"title": "课程目标", "bullets": ["…", "…"], "note": "讲解要点…", "minutes": 5}
  ],
  "download_url": "/files/ppt/<uuid>.pptx"
}
错误：422 / 502 / 504（>180s）
```

### 5.6 教案生成

```text
POST /v1/lesson
请求：{"topic": "用例图教学设计", "minutes": 45}
成功 200：
{
  "lesson": {
    "course_name": "用例图教学设计",
    "teaching_goals": {"knowledge": ["…"], "ability": ["…"], "literacy": ["…"]},
    "key_points": ["…"], "difficult_points": ["…"],
    "teaching_flow": [{"stage": "导入", "minutes": 5, "teacher_activity": "…", "student_activity": "…"}],
    "class_exercises": ["…"], "homework": ["…"]
  },
  "markdown": "# 用例图教学设计\n> AI 生成，请教师审核后使用\n…",
  "missing_fields": [],              // 非空 = 模型输出缺字段（应提示教师补充）
  "download_url": "/files/lesson/<uuid>.docx"
}
错误：422 / 502 / 504
```

### 5.7 统一 API 封装（`js/api.js` 规范）

```js
async function apiPost(path, body, { timeoutMs = 60000 } = {})
```
- 使用 `AbortController` 实现超时（默认 60s；UML 页调用时传 180000）；
- 非 2xx 时抛出带友好文案的 `Error`：422 → 「请求参数有误，请检查输入」；502 → 使用响应 `detail`；504 → 「请求超时，请稍后重试」；其他 → 「服务异常，请稍后重试」；
- 网络失败（`TypeError: Failed to fetch`）→ 「无法连接服务，请确认后端已启动」。

### 6.3 UML 建模页 `uml.html`（第一优先级，最完整链路）

**目的**：教师输入一句话需求，得到用例图图片 + 质检报告 + 可编辑源码。

**布局**：上下两栏。上栏「需求输入」卡片；下栏「结果区」（初始隐藏，生成成功后显示）。

```text
┌─ 需求输入卡片 ────────────────────────────────┐
│  标题：描述你的建模需求                         │
│  [textarea 5 行，placeholder="例：学生可以发布商品，  │
│    管理员审核商品，买家可以浏览商品并下单"]          │
│  字数统计：0 / 3000（右侧对齐，超限变红）           │
│  ┌──────────────┐  ┌──────────────┐           │
│  │ 图片格式 [PNG ▾] │  │ [生成用例图]（主按钮）│      │
│  └──────────────┘  └──────────────┘           │
│  示例 chips：[二手交易系统] [图书借阅系统] [在线考试]  │
└──────────────────────────────────────────────┘
┌─ 结果区（生成后显示）────────────────────────────┐
│ ┌─ 左列（55%）：用例图预览 ─┐ ┌─ 右列（45%）：质检报告 ─┐ │
│ │ render.status=rendered:   │ │ 顶部大徽章：✅ 质检通过   │ │
│ │   <img src=download_url>  │ │    或 ⚠️ 发现 N 个问题    │ │
│ │ source_only: 灰底提示框    │ │ issues 表格：            │ │
│ │  「图片未能生成：<reason>」 │ │ 级别徽章 | 规则ID | 说明  │ │
│ │ [下载 PNG]（主按钮）       │ │ （列：级别/规则/对象/建议）│ │
│ └───────────────────────────┘ └────────────────────────┘ │
│ ┌─ PlantUML 源码（可折叠 <details>，默认收起）────────────┐ │
│ │ 等宽字体深色底代码块 + [复制源码] 按钮                   │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

**交互状态**：

| 状态 | 表现 |
|---|---|
| 空输入点击生成 | textarea 红框 + 下方红字「请先输入建模需求」 |
| 生成中 | 按钮禁用改文案「生成中…（约 1 分钟）」；结果区显示骨架屏（灰条动画） |
| rendered | 左列显示图片；右列质检徽章；`passed=false` 时徽章用 `--color-error-light` |
| source_only | 左列灰底提示框显示 `render.reason`，右侧照常出报告；下载按钮隐藏 |
| 502/504 | 错误提示条（`--color-error-light`）显示 detail 文案，输入保留可重试 |

**质检徽章映射**：`passed=true` → 绿「质检通过」；存在 error → 红「未通过质检」；仅 warning/info → 橙「通过（含建议）」。issues 表的级别列用 5.2 节徽章色。

### 6.4 教材问答页 `qa.html`

**布局**：单列对话流（类聊天界面，最大宽 800px 居中）。

- 顶部固定输入条：输入框 + 「提问」按钮；上方一排示例问题 chips（点击填入输入框）：
  `什么是用例图？` `include 和 extend 怎么区分？` `活动图里泳道的作用是什么？` `帮我看看这段需求该怎么建模`
- 提问后：用户消息气泡（右对齐，主色浅底）+ 助手回复卡片（左对齐白卡片）。
- 回复卡片结构：正文（`reply` 按换行分段，`【xxx】` 开头的段落首行加粗）+ 底部「教材来源」折叠区（`sources` 列表：文件名 + snippet 摘要，12px 灰字）。
- 生成中：助手侧三点跳动动画。
- 错误：红色提示条，输入保留。
- 多轮：页面保留历史消息（仅前端内存，不持久化），最多展示 10 轮。

### 6.5 课件与教案页 `resources.html`

**布局**：Tab 切换（下划线式）「PPT 生成」/「教案生成」，两个面板结构相同：

```text
┌─ 表单区 ────────────────────────────┐
│ 课题：[input，placeholder="例：用例图建模入门"]      │
│ 课时：[number input，默认 90（PPT）/ 45（教案）] 分钟 │
│ [生成]（主按钮）                                    │
└────────────────────────────────────┘
┌─ 结果区 ────────────────────────────┐
│ PPT Tab：                            │
│  标题行：title + 徽章「共 N 页」+ [下载 .pptx]        │
│  大纲：sections 列表（名称 + 页数徽章 + points 列表）  │
│  分页预览：pages 卡片网格（2 列）：页标题 + bullets    │
│           列表 + 备注折叠（note，12px 灰字）          │
│ 教案 Tab：                           │
│  顶部黄色提示条：「AI 生成，请教师审核后使用」          │
│  [下载 .docx]（主按钮）                              │
│  结构化渲染：教学目标（三列小卡：知识/能力/素养）       │
│  → 重点/难点（两组列表）→ 教学流程表（环节|时间|教师活动│
│  |学生活动 四列表格）→ 课堂练习/课后任务（编号列表）    │
│  missing_fields 非空时：顶部红字提示「以下字段缺失：…」 │
└────────────────────────────────────┘
```

## 7. 交互与状态规范（全站统一）

| 场景 | 规范 |
|---|---|
| 加载中 | 按钮 `disabled` + 文案加「…」；结果区骨架屏（3 条灰色渐隐条，CSS 动画 `opacity` 1.2s 循环） |
| 成功 | 结果区淡入（`opacity` 0→1，200ms） |
| 失败 | 结果区顶部错误提示条（error-light 底 + error 字 + 12px），文案来自 `api.js` 封装；**不得**显示堆栈或原始 JSON |
| 空态 | 结果区默认不渲染（非空态占位） |
| 请求超时 | UML 页 180s、其余 60s，超时文案见 5.7 |
| 防重复提交 | 请求进行中再次点击无效（按钮 disabled 已保证） |
| XSS 防护 | 所有服务端返回的文本（reply/sources/markdown 等）插入 DOM 时必须用 `textContent` 或转义函数，**禁止** `innerHTML` 直接拼接 |
