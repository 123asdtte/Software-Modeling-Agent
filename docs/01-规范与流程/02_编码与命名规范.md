# 编码与命名规范（v13）

> Python + LangChain 项目。所有代码必须符合本规范，评审以此为检查清单。

---

## 1. Python 编码规范

- Python 版本：3.11+；遵循 PEP 8，使用 `black` 格式化、`ruff` 静态检查。
- 行宽 ≤ 100 字符；缩进 4 空格；UTF-8 编码；文件末尾保留一个换行。
- 类型注解：所有函数参数与返回值必须写类型注解；复杂类型用 `typing` / `pydantic` 模型。
- Docstring：模块、类、公开函数必须写中文 docstring，说明用途、参数、返回、异常。
- 异常处理：
  - 捕获具体异常，禁止裸 `except:`；
  - 业务异常自定义异常类；日志记录堆栈（`logger.exception`）。
- 日志：使用标准 `logging` 或 `loguru`；禁止 `print` 调试残留；日志分级（INFO/DEBUG/WARNING/ERROR）。
- 依赖管理：使用 `pyproject.toml`（或 requirements.txt 锁定版本）；新增依赖必须记录用途。
- 配置：使用 `pydantic-settings` 读取环境变量 / `settings.yaml`，禁止散落硬编码。

## 2. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 模块 / 包 | 小写，下划线分隔 | `uml_agent.py`、`rag_chain.py` |
| 类 | PascalCase | `UMLAgent`、`QAAgent` |
| 函数 / 方法 | snake_case，动词开头 | `generate_uml()`、`check_boundary()` |
| 变量 | snake_case | `user_question` |
| 常量 | 全大写下划线 | `MAX_RETRY_TIMES` |
| 配置字段 | snake_case | `model_name` |
| 数据库表 / 字段 | 小写下划线 | `course_material`、`user_memory` |
| Git 分支 | `main` / `develop` / `feature/<模块>-<描述>` | `feature/uml-qa-check` |

- 命名要见名知意，禁止拼音缩写、单字母变量（循环变量除外）。
- Prompt 中的中文名（Agent 名、用例名等）保持中文，代码标识符用英文。

## 3. LangChain / LangGraph 使用规范

- Agent 统一基于 LangGraph 编排；Chain 放 `app/chains/`，Agent 放 `app/agents/`。
- 所有 Prompt 放 `app/prompts/`，禁止散落在代码里；Prompt 版本化，修改要记录。
- LLM 调用统一走 `app/models/llm.py` 的工厂方法，禁止各处直接实例化模型。
- 工具（Tool）放 `app/tools/`，实现必须带输入输出 schema（`pydantic`）。
- 长文本 / 大文档处理必须走 RAG（`app/chains/rag_chain.py`），禁止把整本教材塞进上下文。

## 4. 项目目录与文件命名规范

遵循 v13 PRD 目录结构，并作如下约定：

```
AI-Education-Agent/
├── app/
│   ├── main.py              # FastAPI 入口
│   ├── agents/              # qa_agent / ppt_agent / lesson_agent / uml_agent
│   ├── chains/              # rag_chain / uml_chain / generation_chain
│   ├── tools/               # plantuml_tool / ppt_generator / document_reader
│   ├── knowledge_base/      # textbooks / courses / embeddings
│   ├── prompts/             # qa_prompt / uml_prompt / teacher_prompt
│   ├── models/              # llm.py（模型工厂）
│   ├── database/            # user_memory.py
│   └── config/              # settings.yaml
├── tests/                   # 与 app 目录结构一一对应的测试
├── docs/                    # 指向本开发文档体系的说明
└── README.md
```

- 文档（开发体系）统一放在仓库 `docs/` 目录（2026-09-22 随仓库化迁移），按 `01-规范与流程 / 02-需求文档PRD / 03-技术方案 / 04-项目管理` 组织。
- 新增文件必须先考虑是否已存在同类，遵循"先读后写、能复用不复写"。

## 5. 代码质量红线

- 禁止硬编码密钥 / Token / 数据库口令。
- 禁止在代码中拼接用户输入直接执行命令（防注入）。
- 禁止提交 `__pycache__`、`.env`、数据快照、临时文件到 Git。
- 禁止提交未经测试的函数；新增函数必须配至少一个单元测试。

## 6. AI 辅助开发规范

- 使用 AI 生成的代码，提交前必须人工 review，并在 PR 描述中注明"AI 辅助生成"。
- AI 生成的代码必须经过：类型检查（mypy）+ 静态检查（ruff）+ 单元测试通过。
- AI 生成的 Prompt / 文档同样要人工核对事实（模型名、接口、依赖版本等）。
