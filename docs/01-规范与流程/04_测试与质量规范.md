# 测试与质量规范（v13）

> 测试是交付的底线：**没有测试的功能不算完成**。验收标准见 `04-项目管理/02_验收标准与Demo脚本.md`。

---

## 1. 测试层级

| 层级 | 对象 | 工具 | 目标 |
|---|---|---|---|
| 单元测试 | 函数 / Chain / Tool | pytest | 每个业务函数至少 1 个用例 |
| 组件测试 | Agent（单个） | pytest + 模型 mock | Agent 主流程 + 边界 |
| 集成测试 | 多 Agent + RAG | pytest | 全链路可跑通 |
| 评测（Eval） | RAG 检索 / UML 质检 | 评测用例集 | 质量可量化 |
| 端到端 | Web → API → Agent | Demo 脚本 | 演示可用 |

## 2. 单元测试要求

- 测试文件与 `app/` 目录一一对应：`app/agents/uml_agent.py` → `tests/agents/test_uml_agent.py`。
- 用例命名：`test_<行为>_<场景>`，如 `test_check_boundary_rejects_database_as_actor`。
- 外部依赖（大模型、向量库）一律 mock，保证测试快速、确定性。
- 覆盖率目标：核心模块（uml_agent、rag_chain、plantuml_tool）行覆盖率 ≥ 80%，全项目 ≥ 60%。

## 3. UML 质检评测集（核心）

建立固定评测用例集 `tests/fixtures/uml_cases.json`，包含：

| 类别 | 用例示例 | 期望结果 |
|---|---|---|
| 边界-正确 | 学生、管理员作为 Actor | 通过 |
| 边界-错误 | 数据库作为参与者 | 拦截：系统内部组件不能作 Actor |
| 粒度-错误 | "点击提交按钮"作为用例 | 拦截：是操作步骤，不是业务目标，建议"提交订单" |
| 完整性-缺失 | 漏掉"买家"角色 / 漏核心功能 | 提示补全 |
| 关系-错误 | include/extend 关系错误 | 提示纠正 |
| 双重验证 | 规则校验通过但 LLM 复核发现矛盾 | 二次拦截 |

- 每次改动 UML 相关代码必须回归全部评测用例。
- 评测结果记录在 `tests/eval_report.md`（通过率、失败原因、模型版本）。

## 4. RAG 检索评测

- 建立 QA 评测集（≥30 问），覆盖：概念解释、教材关联、边界问题。
- 指标：检索命中率（top-k 是否命中答案来源）、回答正确率、引用可追溯率。
- 目标：top-3 检索命中率 ≥ 90%；回答必须可追溯到教材来源。

## 5. 质量门禁（CI，合入前必须全过）

1. `ruff check .` —— 无错误；
2. `mypy app` —— 类型检查通过；
3. `pytest --cov` —— 全绿且覆盖率达标；
4. 安全扫描：依赖漏洞（`pip-audit`）、密钥扫描（gitleaks 或等价）；
5. UML 评测集回归通过。

## 6. 缺陷管理

- 缺陷记录：现象、复现步骤、影响范围、期望行为、严重级别（阻塞/高/中/低）。
- 阻塞级缺陷未修复不得发布；高缺陷未修复不得验收。
- 修复必须补回归测试，防止复发。

## 7. 性能与稳定性

- RAG 问答首响 ≤ 5s（内网模型）；PPT/教案生成 ≤ 60s；UML 生成 ≤ 30s。
- 大模型调用必须超时与重试（指数退避），失败有兜底回答。
- 上传文件（PDF/PPT/教材）大小与格式校验；长文档分块处理，不超上下文。

## 8. 演示保障

- 正式演示前跑通 `04-项目管理/02_验收标准与Demo脚本.md` 的完整 Demo 脚本。
- 演示环境使用固定账号、固定评测数据，避免随机性（模型温度调低、关闭随机）。
- 备好离线兜底：网络异常时演示用例仍可展示（缓存结果或本地模型）。
